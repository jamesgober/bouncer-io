# bouncer-io v0.3.0 - Core

**The door, ban memory, and tickets work.** v0.3.0 is the first release with functional code: a banned address, prefix, or identity is refused at the door before a byte is read, every admitted connection and request carries a ticket, and a checkpoint costs one atomic load until something is revoked.

## What is bouncer-io?

<strong>bouncer-io</strong> is the door guy. It refuses banned sources at accept, before a byte is read, and revokes requests that are already running: the next checkpoint a revoked request crosses wipes what it collected, replaces the response with a generic denial, closes the connection, and remembers the offender. Rate limiting is one tool inside the door, not its purpose.

## What's in 0.3.0

- **The door.** `Bouncer::door(peer)` checks trusted proxy hops, the allow list, and ban memory from the peer address alone, and issues a connection ticket. A refusal is a `Refusal` value for logs; the peer sees the same abortive close whatever the reason.
- **Ban memory.** Bans by address, prefix of any length, session, account, tenant, fingerprint, and fingerprint within a prefix. IPv6 clients are keyed at /64, because one host controls its whole /64. Timed bans grow for repeat offenders, with a cap and jitter; only administrators, the application, and sentinel ban permanently. Allow-listed keys and trusted proxies are never banned. The table is bounded and evicts only expired entries and timed bans from local heuristics.
- **Readers never wait.** The ban table is read through per-slot sequence locks with eight one-byte tags per group, so a miss touches only a few tag words; administrator prefixes live in a compiled multibit trie read through a per-thread cache.
- **Tickets and checkpoints.** `Ticket::request`, `Ticket::checkpoint`, and `Ticket::bind_client` for the real client behind a trusted proxy. A request whose connection is gone is denied; a request under a proxy hop is denied until its client is bound.
- **Strict parsing.** `Cidr::parse` refuses zone ids, whitespace, and leading zeros, reports the byte position of the first error, and is fuzzed.
- **Tests.** Edge cases and threat tests, property tests, loom models for the ticket free list and the table slots, and a counting-allocator test showing that the door, request, checkpoint, and `bind_client` paths do not allocate.

## Performance, first measurement

On a shared development machine: the checkpoint fast path costs about 1.1 ns. The door with 1,000,000 bans and random peers costs 230 to 360 ns per call, above its 100 ns p99 target. Where the time goes and the plan to close the gap are recorded in `dev/PLAN.md` section 11.1; the target is an exit criterion of 0.6.

## What's next

`0.4.0` adds in-flight revocation by connection, request, session, account, tenant, prefix, and fingerprint, wipe-replace-eject with the zeroizing `Collected` buffer, strikes (observe by default), door budgets, and events.
