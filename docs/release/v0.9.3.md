# bouncer-io v0.9.3 - Gate tag

**bouncer behind serve-net with no map of its own.** serve-net 0.7 carries the tag a gate returns at the door on every request of the connection, so the `Bouncer` is handed to the server as its gate as it is, and each request takes its connection's ticket straight from the envelope. The example and the tests lose the map from connection id to tag, the mutex around it, and the wrapper type that kept it. Upgrade from 0.9.2; the API is unchanged.

## What is bouncer-io?

<strong>bouncer-io</strong> is the door guy. It refuses banned sources at accept, before a byte is read, and revokes requests that are already running: the next checkpoint a revoked request crosses wipes what it collected, replaces the response with a generic denial, closes the connection, and remembers the offender. A checkpoint costs one atomic load until something is revoked. Rate limiting is one tool inside the door, not its purpose.

## Behind serve-net

```rust,ignore
let bouncer = Bouncer::new();
let site = serve_net::Server::builder()
    .listener(ListenerSpec::tcp("web", "127.0.0.1:8080"))
    .gate(bouncer.clone())
    .serve(Site { bouncer })?;

// In the service's `head`:
let tag = TicketTag::from(env.gate_tag());
let Ok(mut request) = self.bouncer.request(tag, id) else {
    return HeadAction::refuse(503);
};
```

Before 0.9.3 an integration wrapped the `Bouncer` in a gate of its own that recorded each connection's tag in a map under a mutex at admit, looked it up on every request, and removed it at close. That lock on every request is gone. serve-net's envelope grows 8 bytes per connection to carry the tag; bouncer's own costs are unchanged. `examples/guarded_http.rs` is the whole integration, and `docs/INTEGRATION.md` shows the call.

## Changed

- The `net-io` feature requires net-io 0.6.2 or later: the version serve-net 0.7 requires and the one tested. 0.6.0 and 0.6.1 carry defects fixed in 0.6.2.
- The feature stays on net-io 0.6 for now. net-io 0.7.0 is published with the same `Gate` trait, but Cargo treats 0.6 and 0.7 as two crates, and bouncer's gate must be the one serve-net calls. It moves to net-io 0.8 together with a serve-net on 0.8. That release brings a bounded flush-then-close after a denial, so a Windows client gets the 403 instead of a reset, and `close_after_flush` by id for `NetIoEjector` (PLAN D-135).

## Verification

- A new test sends four requests on one kept-alive connection through serve-net. Each is judged against that connection's ticket, and the fourth, after its session is revoked, is the generic 403.
- The serve-net tests pass with the map removed. Without the tag every logged-in request would be refused 503, so they fail if the tag does not arrive.
- `cargo fmt`, clippy with all features and with none, tests, docs, and `cargo package` on Windows and Linux, stable and 1.85.

## Upgrading from 0.9.2

Change the version to `0.9.3`. If you run bouncer behind serve-net, move to serve-net 0.7.1. Then delete your connection-id-to-tag map and give the `Bouncer` to `.gate(...)`. Take each request's tag with `TicketTag::from(env.gate_tag())`. Behind any other transport, nothing changes.

## What's next
