# bouncer-io v0.10.0 - Simple

**The same bouncer, with fewer ways to say each thing.** An audit of every public item against the simple-API rule found nine places where the API was harder to use than it had to be. This release fixes all nine. `bouncer.door(peer)?` now works in any function that returns `BouncerError`. A ban or a lift with options has one builder instead of two. Names are spelled out, and the builder takes its plug-ins as they are. It also fixes every finding of an independent security and performance review. It is a breaking release, and the migration from 0.9 is below. The door, the ticket, and the checkpoint run exactly as they did.

## What is bouncer-io?

<strong>bouncer-io</strong> is the door guy. It refuses banned sources at accept, before a byte is read, and revokes requests that are already running: the next checkpoint a revoked request crosses wipes what it collected, replaces the response with a generic denial, and closes the connection, and a ban keeps the offender out at the door. A checkpoint costs one atomic load until something is revoked. Rate limiting is one tool inside the door, not its purpose.

## What changed

- **`?` on the door.** `Bouncer::door` still returns the small `Refusal`, and that now converts into `BouncerError::Refused`. The first call every user writes compiles in a function that returns `Result<_, BouncerError>`.
- **One options builder.** `ban(key)` and `lift(key)` take a key: an address, a `Cidr`, or any `BanKey`. A duration, an actor, a reason, or evidence goes through the same `Directive` every other layer of the stack sends: `bouncer.apply(Directive::ban(key).for_duration(d).by(actor))`. `BanSpec` and `LiftSpec` set the same fields as `Directive` and are gone. `Target` gains `FingerprintIn`, so a directive bans every key `ban` does.
- **Names.** `ConnId` is now `ConnectionId`, the name net-io uses for the same thing. `Ticket::conn` is now `Ticket::connection`, `Subject::conn` is now `Subject::connection`, and `Delta::last` is now `Delta::last_sequence`. `BouncerBuilder::try_build` is now `build`, since no panicking `build` ever existed.
- **Plug-ins by value.** `event_sink`, `ejector`, `denial_format`, `clock`, `persistence`, and `version_anchor` take the value. The caller no longer picks between `Arc` and `Box`. An `Arc` you keep still works, such as an ejector you attach to the transport later.
- **`is_cancelled` is gone.** It was `checkpoint().is_deny()`, which is what loops now call.
- **Docs.** The crate-level docs describe the crate as it is, Tier 1 first. `docs/API.md` lists every public item, checked by a script against rustdoc's output.

The audit also records what stays and why (`dev/API-AUDIT-0.10.md`). Checkpoints return `Verdict`, not `Result`: a denial has to be wiped and replaced where it happens, and `?` would carry it away from the buffer it must wipe. `revoke` keeps its reason, because the reason is what the application knows at the call and what the audit trail records. The door keeps its name.

## Security and performance review

An independent review of 0.9.3 found no critical issue, one high, six medium, five low, and three notes. All are fixed here, each with a test that failed before its fix:

- **Shared addresses need real evidence and keep ceilings.** An address counts as shared by many people (a NAT) only on evidence a client cannot mint. That means many distinct accounts in an hour, or a range the deployment names with `SharedAddresses::known`. Sessions no longer count, and detection can be turned off.
  - A shared address is throttled at its threshold, and the throttle now slows it at the door.
  - A second threshold while it is throttled bans it.
  - Its strikes do not add up to a ban of its prefix.
  - Only named ranges keep escalation off a prefix.
- **Clients behind an HTTP proxy are budgeted.** A client named by a forwarded header is charged the door budgets once per request, as a PROXY-protocol client is once per connection.
- **Strikes never switch off.** The strike counter table is sized by `strike_capacity`, 262,144 by default. A full probe path gives the newcomer the slot with the fewest strikes, so a flood of one-strike keys cannot push out a key near its threshold. A sampled event reports when the table is full, and each counter expires by its own kind's window.
- **Datagrams earn no exemption from their source address**, which UDP lets anyone forge, until the protocol has verified it.
- **The revocation table empties itself.** A full table reclaims, inline, what no live ticket needs, so a bouncer with no maintainer thread does not stay full.
- **Bulk loads are linear.** `Bouncer::apply_all` builds the administrator prefix set once per batch, so a 20,000-prefix blocklist loads in seconds rather than minutes.
- **Smaller fixes.**
  - Racing allow-list reloads always leave the door reading the list that won.
  - `Collected::clear` and `truncate` wipe bytes written through `spare` and never committed.
  - `ipv6_lengths` must include 64.
  - `Refusal::Posture` is removed, since nothing produced it.
  - Fingerprint binds no longer allocate.
  - The per-thread caches serve four bouncers per thread.
  - Several doc statements are corrected to match the code.

The cost a deployment will notice: a NAT throttled for an attacker among its users admits a quarter of its prefix budget until the throttle ends (one base ban length, 10 minutes by default). In the replay of 2,000 users behind one address, 52% of connections were admitted during the throttle and no request was denied. Before, they were all admitted, and so were the attacker's connections.

## Cost

None at run time. The door, ticket, and checkpoint paths compile to the code they did, and CI's instruction-count gate checks that. A shared `Arc` sink or ejector given to the builder is called through one more pointer, on paths that are already cold.

## Upgrading from 0.9

| 0.9 | 0.10 |
|---|---|
| `bouncer.ban(BanSpec::address(a))` | `bouncer.ban(a)` |
| `bouncer.ban(BanSpec::key(k).for_duration(d).by(x).because(r))` | `bouncer.apply(Directive::ban(k).for_duration(d).by(x).because(r))` (the id is `applied.ban`) |
| `bouncer.lift(LiftSpec::key(k).by(x).because(r))` | `bouncer.apply(Directive::lift(k).by(x).because(r))` (the count is `applied.lifted`) |
| `ConnId`, `ticket.conn()`, `subject.conn` | `ConnectionId`, `ticket.connection()`, `subject.connection` |
| `Bouncer::builder()...try_build()` | `Bouncer::builder()...build()` |
| `.event_sink(Arc::new(sink))`, `.persistence(Box::new(store))` | `.event_sink(sink)`, `.persistence(store)` (an `Arc` or a `Box` you already hold still works) |
| `request.is_cancelled()` | `request.checkpoint().is_deny()` |
| `delta.last()` | `delta.last_sequence()` |
| `match` on `BouncerError` | add an arm for `Refused`, or keep the wildcard (the enum is non-exhaustive) |
| `match` on `Refusal` with a `Posture` arm | remove the arm; the strict posture refuses with `OverBudget` |
| `metrics().refused_posture` | removed (it was always 0) |
| `ipv6_lengths(&[...])` without 64 | add 64 |
| shared addresses detected by sessions | nothing to do if your users log in (accounts count); otherwise name your NAT ranges with `.shared_addresses(SharedAddresses::detect().known(&ranges))` |
| behind an HTTP proxy, with forwarded headers | each request is now charged the door budgets; size `Budgets::door_rate` and `door_concurrency` for requests |

For gateway-io, the one dependent in the stack (`crates/gateway-io/src/bouncer.rs`):

```rust
use bouncer_io::{Actor, AllowList, Bouncer, BouncerError, Cidr, Directive, EventSink, NetIoEjector, Reason, TicketTag};

pub fn ban(bouncer: &Bouncer, addr: IpAddr) -> Result<(), BouncerError> {
    bouncer
        .apply(Directive::ban(addr).for_duration(CONFIG_BAN).by(Actor::Admin(0)).because(Reason::ADMIN))
        .map(|_| ())
}

pub fn lift(bouncer: &Bouncer, addr: IpAddr) -> Result<(), BouncerError> {
    match bouncer.apply(Directive::lift(addr).by(Actor::Admin(0)).because(Reason::ADMIN)) {
        Ok(_) | Err(BouncerError::NotFound) => Ok(()),
        Err(e) => Err(e),
    }
}

// in `build`: `builder.try_build()?` becomes `builder.build()?`.
```

`.ejector(ejector.clone())` with an `Arc<NetIoEjector>` and `.event_sink(sink)` with an `Arc<dyn EventSink>` compile unchanged. gateway-io was built and tested against this release with those changes. Behind a load balancer it now charges each client per request, so its `door.*` budget settings should be sized for requests. Its configuration bans can go through `apply_all` in one batch.

## Verification

- New tests (`tests/api.rs`):
  - `?` on a refusal;
  - a key-only ban is by the application with the policy duration;
  - a directive sets what the key-only call cannot;
  - a host-length prefix ban is the address ban;
  - a fingerprint ban within a prefix, with its lift;
  - `FingerprintIn` refused as a revocation or throttle target;
  - plug-ins passed by value and as a kept `Arc`.
- The review's findings, as regression tests (`tests/review.rs` and unit tests), each failing before its fix.
- Every existing test, doc test, loom model, and fuzz target passes on the new API. `directive_sequence` and `journal_replay` were fuzzed for 10 minutes each.
- `cargo fmt`, clippy with all features and with none, tests, docs, and `cargo package`, on Windows and Linux, on stable and 1.85.
