# bouncer-io v0.11.0 - Transport

**The `net-io` feature moves to net-io 0.7.2 and serve-net 0.8.1.** Every serve-net from 0.4.0 to 0.7.1 is yanked for two security defects. serve-net 0.8 fixes them and is built on net-io 0.7, and bouncer's gate has to implement the net-io the server calls, so the feature moves with it. bouncer's own API is unchanged. Behind any other transport there is nothing to do but change the version.

## What is bouncer-io?

<strong>bouncer-io</strong> is the door guy. It refuses banned sources at accept, before a byte is read, and revokes requests that are already running: the next checkpoint a revoked request crosses wipes what it collected, replaces the response with a generic denial, and closes the connection, and a ban keeps the offender out at the door. A checkpoint costs one atomic load until something is revoked. Rate limiting is one tool inside the door, not its purpose.

## Changed

- The `net-io` feature requires net-io 0.7.2 or later (from 0.6.2). The `Gate` impl, the conversions between bouncer's and net-io's ids and tags, and `NetIoEjector` now use net-io 0.7's types. net-io 0.7.2 is a security release, and its `Gate` trait is the one 0.6 had, so bouncer's code did not change.
- The tests and `examples/guarded_http.rs` run on serve-net 0.8.1.
- Builds clean under clippy 1.100. The instruction-count gate in CI now finds the bench binary through Cargo's own output, since Cargo 1.100 no longer builds it in `target/release/deps`. If the binary or valgrind is missing the gate fails; it never skips.

## Cost

None at run time. The door, ticket and checkpoint paths compile to the same code, and the instruction-count gate in CI checks them against the baseline within 5%.

## Upgrading from 0.10

Behind serve-net or net-io, move all three together, since one net-io version must be in the build:

```toml
bouncer-io = { version = "0.11", features = ["net-io"] }
serve-net = "0.8.1"
net-io = "0.7.2"
```

No code changes in bouncer's calls. Check serve-net 0.8's own release notes for changes on its side. Without the `net-io` feature, change the version to `0.11` and nothing else.

## Verification

- `cargo fmt`, clippy with all features and with none, tests, docs, and `cargo package` on Windows (stable, 1.100 and 1.85) and Linux (stable and 1.85), plus the loom models and a short fuzz run on Linux.
- The serve-net tests and the net-io gate tests pass on serve-net 0.8.1 and net-io 0.7.2, with one net-io version in the build.
