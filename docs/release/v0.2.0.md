# bouncer-io v0.2.0 - Design Lock

**The public API, written down and locked.** v0.2.0 fixes every public type, trait, and signature of bouncer-io before the code is written, and rewrites the plan from the crate's full specification. There is no functional code in this release; the API lands version by version from 0.3.0.

## What is bouncer-io?

<strong>bouncer-io</strong> is the door guy. It refuses banned sources at accept, before a byte is read. Inside, it revokes requests that are already running: the next checkpoint a revoked request crosses wipes what it collected, replaces the response with a generic denial, closes the connection, and remembers the offender so the next attempt dies at the door. A checkpoint costs one atomic load until something is revoked.

## What's in 0.2.0

- `docs/API.md`: every public item with its tier, grade, version, cost target, errors, and examples. The door, tickets and checkpoints, in-flight revocation by connection, request, session, account, tenant, prefix, or fingerprint, the zeroizing `Collected` buffer and wipe-replace-eject, ban memory with prefix escalation and the allow list, directives from other security modules, strikes, budgets, events with a signal catalog, persistence, sharing of bans and revocations across nodes, health, and the net-io gate.
- A one-line API for the common cases: `bouncer.door(peer)?`, `conn.request(id)?`, `request.checkpoint()`, `request.deny_and_eject(&mut reply)`, `bouncer.ban(addr)?`, `bouncer.revoke(session, Reason::LOGOUT)?`.
- `dev/PLAN.md` rewritten: requirements, the enterprise and distributed design, 27 threats with their tests and costs, 71 edge cases, answers to every open decision, and decisions D-009 to D-035.
- Local heuristics now observe by default: bouncer's own strike thresholds report what they would ban and ban nothing until a project switches a category to enforce. Explicit commands always act.
- The net-io hook shape agreed with net-io's own design lock: one `Gate` trait with a per-connection ticket, so the check before every socket write is one atomic load.
- `dev/ROADMAP.md` on the portfolio series: 0.3 core, 0.4 extended, 0.5 feature complete, 0.6 optimisation, 0.7 hardening, 0.8 alpha, 0.9 beta.
